# Creative Passport「创意护照」产品需求文档（PRD）

版本：V1.2 · 2026-11-24  
状态：需求设计稿，待开发与用户验证  
本次更新：明确网页产品、邀请登录、模型分工、创意优先的交互流程；保留 TikTok 三层投放口径；根据现有 `aigc-creative-lab` 仓库，调整为在已有 Web 产品上持续升级。

## 1. 产品定义与核心价值

### 1.1 产品是什么

**一个面向出海品牌和代理商的 AI 广告创意网页工具：把商品资料转成不同市场的创意方向、脚本、分镜和短视频，并支持修改、评价、版本追溯和素材导出。**

用户通过浏览器登录使用。以电脑端完成上传、对比和编辑，手机端支持查看成片与参与评价。首版不开发原生手机 App。

核心是一条有人工确认点的 AI 工作流程：AI 理解资料和提出候选，程序负责校验、保存与视频合成，用户决定哪些事实可信、选择什么创意、采用哪一版。首版不提供自主投放、自动竞价或自动发布。

### 1.2 解决谁的什么问题

目标用户是为商品制作海外素材的品牌营销人员、跨境商家和代理商创意策划。他们已有商品图、功能说明或实拍片段，希望进入另一个市场，但会遇到：

- 直接翻译容易忽略使用情境与表达习惯，随意重写又可能改变商品信息。
- 在聊天、配音、图片和剪辑工具之间反复搬运，品牌规范和确认结果容易遗漏。
- 修改后难以追溯采用原因、资料版本、制作成本及目标用户反馈。

**核心价值是缩短从商品资料到可审核广告候选的过程，并降低跨市场制作与修改中的信息丢失。** 是否真正减少返工、提高采用率，需要通过真实使用验证。

### 1.3 首版成功的判断

1. 一个受邀用户能独立完成上传、事实确认、创意选择、视频制作、修改和导出。
2. 广告中的商品声明有确认来源，内容与目标市场、广告目标和目的地相符。
3. 能根据真实用户反馈完成一次有记录的迭代，并报告质量、采用、耗时和费用。

首版不以证明 ROI 或 GMV 提升为成功标准。目标用户偏好、模型评分和实际购买是不同证据，分别记录。

## 2. 首版范围与用户角色

### 2.1 固定范围

| 项目 | 首版决定 |
|---|---|
| 产品形态 | 可登录的网页工具；电脑端创作，手机端查看与评价 |
| 开放方式 | 免费邀请制 Beta，暂不开放自助注册、付费订阅或团队协作 |
| 品类与样本 | 便携手动咖啡器具，3 个资料完整、有权使用素材的商品样本 |
| 市场与语言 | 默认美国 `US/en-US`、墨西哥 `MX/es-MX`；正式评价前根据当地反馈资源确认 |
| 创意数量 | 3 个商品×2 个市场×基础版/场景改编版＝12 条首轮成片；最多 6 条反馈驱动的修订片 |
| 内容输出 | 创意方向、脚本、分镜、配音、字幕、15 秒 9:16 成片及改编说明 |
| 制作方式 | 真实商品图/片段＋AI 文案和辅助图＋配音＋模板化合成 |
| 广告场景 | 首版适配 Traffic → Website 的本地投放上下文；不连接 TikTok 账户 |
| 界面语言 | 创作者界面以英文为主；广告文案按目标市场语言生成 |

用户可以先做一个商品、一个市场，不强制凑齐全部演示样本。两个市场是项目验证范围，不是首次使用门槛。

### 2.2 角色与权限

| 角色 | 可以做什么 | 不能做什么 |
|---|---|---|
| 项目创建者 | 管理自己的商品、项目、创意、投放草稿、评价链接及导出文件 | 访问其他用户的资料，操作真实广告账户 |
| 外部评审者 | 通过限时链接查看指定素材并评价 | 编辑项目，查看未开放的原始资料和费用 |
| Beta 管理员 | 邀请用户、设置额度、关闭付费能力、查看必要运行记录 | 首版不建设独立管理后台，使用现有管理工具完成 |

### 2.3 首版不做

原生 App、公开注册、在线付费、基础模型训练、全网抓取、爆款预测、专业时间线剪辑、全目标投放管理、自动发布和竞价不纳入首版。图片生成不保证商品绝对保真，模板合成不宣称为整段视频模型生成。

## 3. 用户交互流程与页面

### 3.1 主流程：先创意，后补投放配置

**受邀登录 → 上传商品 → 确认事实 → 填写创意需求 → 选择方向与脚本 → 生成预览并修改 → 评价与导出。**

| 步骤 | 用户需要做什么 | 系统提供什么 |
|---|---|---|
| 1. 登录 | 输入受邀邮箱，打开登录邮件 | 进入自己的项目，继续未完成任务 |
| 2. 上传商品 | 至少上传清晰商品图和资料；实拍片段可选 | 整理视觉 Spec、功能说明与待确认项 |
| 3. 确认事实 | 核对商品外观、卖点、条件和品牌要求 | 保存确认版本，指出缺失依据与未知信息 |
| 4. 填写创意需求 | 选择市场、语言、受众/场景和广告目标；目的地默认 Website | 给出简短需求摘要，建立必要的本地层级关联 |
| 5. 选择方向 | 比较 3 个场景改编候选，选 1 个；查看基础版作对照 | 展示依据、脚本和分镜，允许编辑后确认 |
| 6. 制作与修改 | 确认费用，预览视频；只修改不满意的文字或镜头 | 调用模型、合成视频、检查问题，保存版本与费用 |
| 7. 评价与导出 | 自查，邀请目标用户评价，选择候选版本下载 | 素材包、原始反馈、修改记录与未验证项 |

预算、排期、出价、身份、具体 URL 等属于“投放草稿”区域，可以后补。缺少这些信息不能阻断早期创意探索；缺少商品依据、市场、语言、受众描述或目标时，则不能开始正式内容生产。

### 3.2 页面结构

| 页面 | 重点内容 |
|---|---|
| 首页 / 登录 | 产品用途、邀请入口、邮箱登录及错误提示 |
| 我的项目 | 自己的项目、当前步骤、最近版本、任务状态和 AI 费用 |
| 商品资料 | 原图/片段、可编辑 Spec、确认后的事实与品牌规范 |
| 创意需求与方向 | 市场卡、需求摘要、3 个候选方向及基础版对照 |
| 创意工作台 | 分镜、文案、视频预览、局部修改、版本比较与费用 |
| 评审与结果 | 素材审核、盲评链接、原始反馈、采用与修改记录 |
| 投放草稿 | Campaign / Ad Group / Ad 树、字段配置、变更影响与导出清单 |

主导航围绕商品、创意和素材展开，三层投放树放在投放草稿页面；工作台仅常驻显示相关目标、市场、受众、目的地及所属路径，避免把产品做成需要先填完投放大表单才能使用的工具。

### 3.3 首次进入与返回继续

首次登录进入空项目页，可创建项目或查看明确标记的演示项目；演示数据不冒充用户真实成果。返回时进入最近项目，恢复到已保存步骤。页面刷新或关闭不取消后台任务，重新进入可查询结果。未保存的编辑需要离开提示。

## 4. 核心功能需求

下列 P0 为首版发布要求，P1 为验证后扩展。现有代码基础与待新增项在第 10 节单独说明。

### FR-01 邀请登录、私有项目与额度（P0）

- 沿用现有 Supabase 邮箱链接登录：管理员先邀请用户，登录不自动创建未知邮箱账户；不新增密码和公开注册流程。
- 用户只能读写自己的项目和文件。所有接口在服务端校验登录和归属，不能只依赖前端隐藏按钮。
- 用户不填写模型 API Key。服务端统一调用模型，并在真实付费调用前检查用户额度、项目费用上限和能力开关。
- 额度由管理员配置，试用账号默认每天最多提交 5 个媒体生产任务；幂等重发不重复占用次数，已开始调用的重试另计实际费用。文字请求另设限流。
- 生产环境关闭开发登录与匿名入口；邀请邮件不可用、会话过期、额度不足或能力关闭时，明确说明并保留已保存内容。

**验收：**受邀用户可登录、退出和返回；未受邀邮箱不能自行注册；跨用户请求被拒绝；原始素材没有永久公开链接；余额或次数不足时不会发生新的付费调用。供应商账单告警不能代替应用内额度检查。

### FR-02 商品 Spec、事实与来源确认（P0）

上传支持 JPG/PNG/WebP 和 MP4。图片每张不超过 10 MB，视频每个不超过 100 MB、60 秒；检查实际 MIME、大小和时长，不只检查扩展名。复用现有 1～3 张参考图上传能力，视频作为新增素材类型。

模型整理外观 Spec 与事实草稿。图片可辅助识别颜色、形状、部件和可读标识，但不能凭图片推断功能、材质或认证。功能与规格由用户提供文字依据并确认；未知信息留空。

每条事实记录 ID、内容、来源摘录、确认状态、版本及适用条件。价格/优惠可选，额外记录市场、币种、条件和有效期。视觉 Spec、功能事实、品牌语气、当次拍摄风格分别保存，避免互相混入。

**验收：**没有来源或未确认的声明不能进入正式脚本；保存后生成不可变快照；后续修改不覆盖旧素材引用。对于旧项目已丢失的历史 Spec，不伪造版本内容，明确标记不可完整回溯。

### FR-03 创意需求与市场参考（P0）

最少收集商品、市场/语言、具体受众或使用情境、广告目标、目的地类型、品牌要求。首版提供 Traffic / Website 默认值，其他目标不假装已适配。

每个市场先整理 5～8 条有来源、有日期的参考，可以来自当地访谈、商品页面或可合法使用的案例。区分商品证据、市场参考与待验证创意假设；只有经确认的商品证据才能支撑功能声明。

使用 `market_code` 和 `locale` 分开表示地区与语言。旧的“欧洲”“东南亚”是宽泛区域标签，不能直接作为一个国家或一种语言的已验证市场。不得自动从国籍推断性格、偏好或场景。

**验收：**一个市场也能开始；可以看到每个改编建议的参考或假设标记；已有按国家固定场景/语气的规则需改为可编辑的候选建议，不能宣称是消费者事实。

### FR-04 创意方向、基础版与脚本选择（P0）

每个商品/市场先给出 3 个 B1 候选方向，包含受众、情境、开场、核心卖点、证明方式、CTA、事实 ID、参考 ID 及改编理由。用户选择 1 个后，生成并编辑脚本与分镜，不同时制作所有候选媒体。

- **B0 基础版：**使用人工确认的英文主稿；美国版本沿用主稿，墨西哥版本准确自然地翻译，保留叙事和卖点顺序。
- **B1 场景改编版：**在相同商品事实与投放背景下，依据参考和当地反馈改写开场、场景、故事或卖点顺序。

两版都保留商品 Spec、参考图与品牌约束，不能把商品保真机制也当作本轮改编变量。对同商品同市场，尽量统一时长、模板、商品条件、配音档位、受众、目标和目的链接；不故意制作低质量 B0。

用户可以修改脚本、拒绝方向并记录原因。审阅译文与正式广告语言分开，不能把中文或英文审阅解释误烧录到其他语言广告中。

**验收：**未选方向、未确认脚本时不开始媒体付费调用；能解释 B0/B1 改了什么；每个商品声明可回到确认事实。第一轮比较整套改编方案，不推断某一句话的独立效果。

### FR-05 素材生产、视频合成与费用确认（P0）

| 环节 | 模型/程序的职责 | 确认点 |
|---|---|---|
| 理解资料、提出方向、写脚本 | 文本/多模态模型输出结构化内容 | 人确认事实、方向和脚本 |
| 辅助图、场景与分镜候选 | 复用参考图条件生成接口，保留身份约束 | 人检查商品外观与适用性，不承诺自动绝对保真 |
| 配音 | 新增 TTS 接口，按确认脚本生成 | 检查发音、语速和是否超时 |
| 字幕、Logo、镜头拼接和导出 | 程序按固定配置合成 | 自动检查格式，人工检查观感 |

最终成片优先使用真实商品图、抠图或实拍操作片段。生成图可以作辅助场景或候选分镜；若主体不准确，替换为原始素材。不能用 AI 画面证明没有依据的容量、效果或使用动作。

没有实拍视频时，允许使用商品图、字幕和镜头运动制作动态视频，并清楚标记其制作方式。首版不依赖整段文生视频，也不将其称为实拍演示。

默认 4 镜头为 3＋4＋5＋3 秒，总长 15 秒；输出 1080×1920、30 fps、H.264/AAC MP4，字幕另附 SRT。原始生成图尺寸不等于成片尺寸，应通过版式、留白或经确认的裁切适配，不拉伸或截掉商品关键部件。

用户开始前看到范围、预估费用和剩余额度。先预留费用，再创建任务；最终记录实际用量和可核对费用。未返回精确费用时标为估算，供应商可能已执行但响应超时时进入待核对状态，不盲目重发。

**验收：**脚本确认后能生成真实可播放视频；生成图、图片动画与实拍来源可区分；字幕不溢出，配音不被静默截断；模板预览与成片用同一配置；关闭网页后仍能查询任务。

### FR-06 局部修改、镜头锁定与版本（P0）

支持改文案、替换镜头、调整顺序、锁定素材和重新制作一个辅助场景。锁定具体文件与配置版本；文字、图片、配音没有变化时复用，不再次调用模型。

修改产生新版本，保存父版本、改动、原因、使用的资料/提示词/模型版本和新增费用。总时长变化、配音超时、字幕异常时提示修正，不随意截断或加速。

**验收：**能比较修改前后并返回旧版本；同一素材被多个 Ad 使用时，旧引用不自动更新；预算或出价变化不会自动重做内容。

### FR-07 质量审核与外部评价（P0）

机器预筛引用、结构、格式和可疑声明；创作者最终检查商品、品牌与语言。模型意见与人工结论分开记录，机器通过不等于事实正确或平台审核通过。

外部评审通过限时可撤销链接查看指定素材，不必创建创作者账号。每个链接/评审会话分配独立匿名参与标识；提交内容在揭示版本前保留，重复提交可识别，不开放项目资料。

评审者知道素材含 AI 辅助制作，但提交前不显示 B0/B1、模型名称或预期结论。随机化播放顺序，保留原始评分、意见、参与者和样本来源。具体研究安排见第 8 节。

**验收：**用户只能评价被分配的素材版本；撤销或过期链接不能继续访问；不能由模型代填当地用户评分；审核分歧可以保留和复核。

### FR-08 导出与结果查看（P0）

- **创意素材包：**MP4、SRT、脚本、版本、改编说明及内部证据清单。需通过人工创意审核；投放字段缺失时标记“创意候选，投放配置未完成”。
- **投放草稿包：**内部 JSON/CSV，包含三层关系、素材关联、已填写字段、缺项、版本与待核验清单；不宣称可直接导入 TikTok。
- **结果页面：**按市场、商品、具体素材版本查看质量、采用、修改、反馈和 AI 费用。没有真实投放数据时，CTR/CVR/CPA/ROAS 显示未验证。

**验收：**创意审核不通过只能导出带预览标记的内部版本；缺少预算或身份不阻断已审核创意包，但草稿包必须列出缺项；任何导出都不创建真实广告或改变广告预算。

## 5. 投放上下文：Campaign → Ad Group → Ad

### 5.1 对象与归属

Project 是本产品的跨市场工作空间，不是 TikTok 的第四层。创意生产批次也不等于投放 Campaign。

| 对象 | 主要设置或内容 | 约束关系 |
|---|---|---|
| Project / Creative Batch | 商品、品牌、参考资料；一次商品的跨市场生产任务 | 组织资料与生产，不定义平台投放层级 |
| Campaign Draft | 名称、广告目标、目的地类型的业务方向、预算分配策略和适用 Campaign 预算 | 可包含多个 Ad Group，决定下层可选配置 |
| Ad Group Draft | 实际地区、受众、语言、版位、优化位置/目标/事件、出价、适用组预算、排期与时区 | 可包含多个 Ad，约束对应市场和素材要求 |
| Ad Draft | 身份/授权说明、素材关联、文案、CTA、商品、具体 URL 和追踪 | 绑定确定的素材版本；一个素材可以用于多个 Ad |

目标、出价、预算、排期、定向都应在完整投放配置中被收集，但不能全部保存成 Campaign 字段。Campaign 摘要可以跨层显示，写入仍按实际归属。

上层目的地类型与 Ad 的具体链接分开；这是本产品的标准化业务模型，不保证与各版本 TikTok 界面或 API 字段一一同名。实际接入需重新映射。

升级版 Smart+ 的一个 Ad 可以包含多个素材与自己的 URL/商品集合，所以数据关系不能永久限制 Ad 等于一个视频。首版只选一个最终视频，保留多素材关联能力。[官方结构](https://ads.tiktok.com/resources/help/article/tiktok-ads-structure?lang=en)、[Smart+ 说明](https://ads-useast2a.tiktok.com/resources/help/article/about-updates-to-smart-plus)

### 5.2 创意模式与完整草稿的区别

用户确认最小创意需求后，系统可自动建立对应的本地草稿关联，无需先填写所有投放字段。按市场复用合适的 Campaign、按商品/市场建立 Ad Group，B0/B1 分别关联 Ad；无法匹配时新建草稿，不凭名称自动合并不同目标的计划。

最终演示样本可形成 2 个 Campaign、6 个 Ad Group、12 个 Ad。它是管理样本的选择，不是平台要求；真实地区定向始终位于 Ad Group，Campaign 名称中的市场只是管理标签。

名称建议：Campaign 为 `市场_目标_商品或业务线_日期`，Ad Group 为 `市场_商品_受众或语言_优化目标`，Ad 为 `商品_B0或B1_版本`。名称不代替唯一 ID。

“完整投放草稿”要求预算、排期、身份和链接等字段补全；“可生产创意”只要求事实与必要创意上下文完备，两种完整性分别判断。

### 5.3 P0 有限支持矩阵

| 配置 | 本地支持范围 |
|---|---|
| 目标 / 目的地 | Traffic / Website |
| 优化 / 出价 | Click，不要求转化事件；不手填目标成本的最大化效果策略 |
| 版位 / 格式 | TikTok，单条竖版视频，手动绑定素材 |
| 地区 / 受众 | US 或 MX，每组一个市场；成年人、宽泛受众，创意受众描述另填 |
| 广告预算 | Campaign budget 或 Ad group budget；DAILY 或 LIFETIME，正数金额，USD |
| 排期 | 完整草稿需每组开始和结束时间，统一使用账户上下文时区 |
| 素材自动化 / 目录 / 平台 Split Test | 不启用，作为后续适配范围 |

这是内部支持集合，不代表任意真实账户可用。其他目标、目的地、优化、出价或自动化组合显示未支持，不能应用为已通过配置。已支持预算策略/类型可切换；不支持的目标变更只做影响预览并阻止应用，原有效配置不变。

账户上下文草稿记录币种、时区、规则版本和来源；默认示例为 USD、Etc/UTC，明确标为本地假设。不能按目标国家推断账户币种或唯一时区。平台最低预算、权限与实际可用性始终属于待核验项，本地通过不代表平台通过。

### 5.4 两类预算与金额语义

| 类别 | 含义 | 关键规则 |
|---|---|---|
| 广告投放预算 | 未来在平台花费的计划，本产品只记录草稿 | 必须有层级、分配策略、日/周期类型、金额、币种和适用时间 |
| AI 制作费用 | 本产品调用模型与重试的支出 | 有用户额度、任务/项目上限、预留、用量、实际或估算费用，不影响广告预算 |

内部广告预算字段至少含 `budget_scope`、`budget_mode`、`amount`、`currency`；AI 费用独立使用 `generation_cost_limit` / `generation_usage`。不能只保存含义不明的 `budget:100`。

- `DAILY` 表示日预算，即愿意每日平均投入的金额，不承诺单日绝对上限；不能命名为 `total_budget`。
- `LIFETIME` 表示对应投放周期的总预算。广告组使用本组排期；Campaign 使用各所属组已确认排期的最早开始至最晚结束，作为本地派生预算覆盖窗口，不增加一个虚构的平台 Campaign 排期字段。
- 没有组或任一组时间未确认，周期预算完整性不通过。不同组可以有不同时间；窗口变化须重新确认预算，不自动增加金额。
- 日预算乘天数只能显示规划估算，不能转换为已设置的总预算。切换日/周期类型必须重新确认金额和时间。
- Campaign budget 下显示统一分配，不伪造组级独立额度或模拟平台分配；Ad group budget 下分别填写各组预算。上层若另有限制，标为限制，不能与组预算重复相加。
- 金额按十进制和币种处理，不混合币种求和。P0 不启用动态预算、自动增额和真实预算扣款。

Smart+ 自动 Campaign 预算的跨组优化与出价约束在 P1 按当前账户和官方规则适配；不能因本地模型简化而宣称所有组合兼容。[预算定义](https://ads.tiktok.com/resources/help/article/budget?lang=en)、[预算策略](https://ads.tiktok.com/resources/help/article/about-budget-strategy-for-your-upgraded-smart-experience?lang=en)

### 5.5 修改影响与兼容性

修改先在编辑区预览，列出新旧值、影响对象、待确认字段和是否需要重做内容。属于支持范围且用户确认后，才写入新配置版本；旧版可回看。

| 修改 | 处理方式 |
|---|---|
| 目标或目的地 | P0 列出下层优化、CTA、链接等影响后阻止不支持的变更；P1 扩展规则后再支持应用 |
| 预算策略 / 类型 | 更新可编辑或继承字段，标记相关组待确认；不自动重做视频 |
| 排期或预算窗口 | 复核周期、金额和促销有效期；过期文案需修改，其他镜头可复用 |
| 地区、受众、语言、版位 | 检查该组下 Ad 的适配；语言不一致提示说明理由，不自动当作违规 |
| 商品事实或品牌规范 | 只标记引用了变更内容的素材及关联 Ad，保留旧快照 |
| Ad 的链接或身份 | 检查当前 Ad 的用途和授权说明，不影响其他广告 |

组级出价、排期和定向的填写规则根据支持矩阵确定，不在 Campaign 重复保存冲突值。未确认的相关字段使草稿保持待复核；重新确认无关字段不能清除全部问题。

目录、自动化和实验的完整适配为 P1。尤其不能将所有 CBO＋Split Test 统一判为支持或不支持，要核对具体测试变量、模式和账户。把两个 Ad 放入同一组既不等于随机实验，也不保证均量分配。[官方兼容性](https://ads.tiktok.com/resources/help/article/split-testing-variables?lang=en)

### 6.1 核心数据

| 数据对象 | 必须保留的关系 |
|---|---|
| User / Project / Product | 创建者与私有项目、商品、素材归属 |
| ProductSpecVersion / Fact / Source | 不可变 Spec、逐条事实、确认与原始依据 |
| MarketBrief / Reference / CreativeBatch | 地区与语言、具体受众、参考与假设、一次生产范围 |

| ReviewSession / Rating / Export / Event | 评价对象、匿名参与者、呈现顺序、审核与导出版本、行为记录 |

本地 ID 与未来平台 ID 分开。保留素材来源是实拍、原图、参考图条件生成、辅助背景还是模板合成；不要仅用统一的“AI 视频”标签掩盖来源。

### 6.2 状态分开管理

- **创意完整性：**资料待补充、脚本待确认、可开始制作。
- **素材版本：**草稿、制作中、待审核、可作为候选、需修改。
- **生产任务：**排队、运行、成功、失败、取消、结果/费用待核对。
- **本地投放草稿：**待补充、待复核、本地规则通过、不兼容。
- **平台核验：**首版固定为未连接账户/待核验，不能出现已发布或平台审核通过。

允许“创意可制作，但投放草稿待补充”，也允许“本地规则通过，但平台待核验”。不能用一个总的通过状态混淆不同环节。

### 6.3 模型与程序边界

沿用仓库已有的文本派生和图像 Provider，先接入现有供应商；TTS 新增独立适配器，模型 ID、能力开关和计价配置化。无需训练基础模型。后续比较第二个模型时走适配器，不为更换供应商重写业务。

模型输出经过 Schema 校验，事实 ID、来源和时长等确定约束由程序检查；语义问题仍由人复核。模型不能自行批准事实、填写评审结果、改变费用上限或执行真实投放。

生产流程采用持久化异步任务，不以一个长 HTTP 请求承担完整视频制作。服务端保存任务再执行，页面查询进度；幂等提交、重启恢复、输入版本快照和结果去重是发布要求。供应商可能已执行的请求先查询或核对，不能无上限重试。

生成脚本和镜头配置不能作为任意可执行代码。模型密钥不发送到浏览器；原始资料作为数据，不作为工具指令。用户删除项目时撤销评价访问，处理未完成任务的晚到结果，并按权限删除文件与业务数据。

### 6.4 行为记录

至少记录需求确认、方向选择、脚本确认、生产提交/完成/失败、人工采用、版本修改、评价提交和导出。事件关联用户或匿名会话、项目、版本和时间，不记录密钥或不必要的个人信息。

## 7. 异常、费用与使用限制

| 情况 | 用户看到什么 / 系统做什么 |
|---|---|
| 邮件限流、过期链接或会话失效 | 明确说明重试或重新登录方式，不丢失已保存项目 |
| 未配置模型、能力关闭或额度不足 | 停止付费调用，允许查看和编辑已有内容 |
| 商品事实、授权说明或创意必填项缺失 | 定位缺项；允许保存，不开始正式内容生产 |
| 预算、排期、身份或 URL 缺失 | 创意可继续，投放草稿明确待补充，导出列出缺项 |
| 模型增加无依据声明或返回错误结构 | 保存失败，最多一次结构修正；仍失败交人工，不把错误结果当素材 |
| 图片已生成但存储失败、响应超时 | 记录可能已发生费用，优先恢复原结果，不重复付费生成 |
| 配音超时、字幕溢出或商品变形 | 标记具体镜头，允许替换或局部重做，禁止直接正式导出 |

费用上限由管理配置确定，不把模型报价写死在需求中。每个任务提交时原子预留，完成后结算实际或估算用量，取消或失败也记录已发生费用。并发任务不能重复占用同一余额。

每条候选的费用包含相关文本、图片、配音及重试；渲染、存储、人工和评审支出另列。先用小样本测得实际成本，再决定 Beta 额度和价格；首版不接在线支付。

## 8. 验证方法与指标

### 8.1 三类验证分开

| 验证 | 比较什么 | 不能得出什么结论 |
|---|---|---|
| 原有商品锚点实验 | 有/无结构化视觉锚点对图片保真的影响 | 不能直接证明新的视频链或跨市场改编有效 |
| 本项目 B0/B1 | 同市场、同商品的基础表达与场景改编 | 不能将结果解释为锚点机制效果或真实购买提升 |
| 后续平台实验 | 满足条件的真实广告表现 | 不能用同组自然分流或不同市场绝对指标替代随机比较 |

原 Python 实验使用文生图对照，产品图像路径使用参考图条件生成；输入条件不同，历史成绩不能直接迁移。新 B0/B1 两版应使用同样的商品保真机制，避免同时改变两个变量。

### 8.2 质量与制作效率

| 指标 | 定义 |
|---|---|
| 关键事实/商品错误 | 人工发现的功能、条件、身份或关键外观错误；未修复时不得作为正式候选 |
| 首次验收通过率 | 首次成片即通过人工审核数 ÷ 首次成片数 |
| 创作者采用率 | 最终采用候选数 ÷ 交付供选择数，保留拒绝理由 |
| 单条合格素材 AI 成本 | 本轮全部相关模型与重试费用 ÷ 合格数；分母为 0 时不输出有效单价 |
| 人工操作 / 总交付时间 | 分别记录实际人工分钟数和含等待的自然耗时 |
| 修改效率 | 一次修改涉及的镜头、调用、费用与耗时，检查是否重做了无关内容 |
| 上下文检查正确性 | 固定用例中层级归属、预算语义和变更传播是否符合本 PRD |

用同等质量的手工流程作为基线，包含单独使用通用模型与剪辑工具的方式。邀请至少 2 位创作者完成可比较任务，交替任务顺序并记录熟练程度；小样本仅报告观察值。

### 8.3 当地用户评价与一次迭代

每市场先请 2 位熟悉当地生活和语言的人审核候选脚本，再招募 12～20 位目标用户探索性评价。记录生活经历、主要语言、使用场景相关性和样本来源；不能只用英语能力代替当地经验。

每人查看本市场 3 组 B0/B1，平衡商品顺序并随机化组内呈现。先询问单条素材的卖点理解、自然度、场景合理性和可信度，再选择更愿意继续观看/了解的版本及原因。一个人产生多条评价时，保留人员分组，不把评分条数当人数。

结果按市场和商品展示分布与原始意见，不声称代表总体或统计显著。选 1～2 个主要问题，修订最多 6 条 B1 后复评；优先使用新参与者，复用原评审者时注明熟悉效应。无改善也如实记录。

### 8.4 模型比较与真实投放

两种文本模型使用固定资料、Schema 和相同图片/合成链。2 个商品用于开发提示词，第 3 个商品的 2 市场×2 版本作为保留任务，每模型执行 2 次，共 16 份保留输出。比较无依据声明、语言、修改量、延迟和费用，保存失败，不发布通用模型排名。根据保留任务调参后，该集不再作为未见数据。

真实投放为 P1：获得账户授权、预算与足够流量后，核对目标、预算策略、自动化和测试变量兼容性，预先固定主要指标、归因与停止规则。Ad 总表现不能复制到每个素材后求和；无对应粒度的数据不强行拆分。品牌和购买目标分别评价，样本不足如实报告。

| 市场规则 | US/欧洲/日本/韩国/东南亚枚举与预置场景 | 规范为地区＋语言；新增 MX，区域旧数据不强行映射为国家；固定叙事改为可验证假设 |
| 生成任务 | 已保存请求、结果和 usage，图片接口仍在 HTTP 请求中执行 | 新增异步生产、幂等、额度预留及费用核对，不能把持久化记录当成已有队列 |
| 评价与视频 | Python 有商品锚点评测；Web 有视频分镜文字 | 新增 TTS、合成、镜头编辑、Web 评价；分镜文字不算已能导出视频 |

现有接口与 UI 的功能基础足够支持持续升级；主要工作是完善数据语义和创意到视频的交付链，暂无必要换技术栈或另起项目。具体已实现证据见第 11 节。

### 10.2 数据与接口迁移原则

1. **先保留历史：**实现前备份数据和存储引用，保留旧入口可查；本次需求更新不直接执行迁移。
2. **拆清 Campaign 语义：**旧 `campaigns` 保留原 ID 与关联，在业务层明确为历史创意批次；新投放对象使用独立 `ad_campaign_drafts`、`ad_group_drafts`、`ad_drafts`，新接口使用独立路径，避免覆盖旧 `/api/campaigns` 的含义。
3. **新增项目与版本：**用项目关联多个商品；新增不可变 `product_spec_versions`、事实来源、市场卡与 `creative_variants`。旧 `market_creatives` 每市场唯一，不直接覆盖来存 B0/B1；新版本引用旧记录作为来源即可。
4. **处理历史缺口：**旧 Spec 表只保存最新内容及递增版本号，不能据旧版本号还原已丢内容。迁移保存当前可得内容与时间，历史缺失显式标记，旧素材仍能查看。
5. **地区迁移：**已有 US 等明确国家可核对映射，欧洲/东南亚保留旧区域标签并要求补具体地区与语言；新市场字段同时调整前端、Schema、SQL 约束、提示词和测试，不只改下拉框。
6. **扩展生产能力：**新增统一 `production_jobs` 编排文本、图片、配音和渲染，旧图片任务保留并关联。素材表扩展视频、字幕和来源类型；图片旧结果不变成伪视频。
7. **保持所有权：**新表和旧数据映射均继承所属用户，迁移与新接口不得绕过原 RLS 和私有文件边界。

### 10.3 分阶段实现与验收

| 阶段 | 实施内容 | 交付门槛 |
|---|---|---|
| A：确认可用基础 | 在原仓库独立分支检查安装、构建、测试、邮箱登录及现有真实 API 链，记录当前失败；准备样本和市场反馈资源 | 得到可复现基线，分清已实现、配置待补与待新增，不依赖 README 的历史描述直接宣称通过 |
| B：资料与轻量创意入口 | 项目、事实来源和 Spec 历史；地区/语言迁移；一个市场也可开始；最小 Brief 与默认草稿关联 | 只填创意必要信息即可完成方向与脚本选择，不被投放字段阻断 |
| C：稳定视频交付 | 新增 TTS、模板合成、字幕、镜头编辑、异步任务、幂等和费用预留；复用现有图片 Provider | 一条真实 15 秒视频可制作、局部修改、恢复任务并导出，费用可追溯 |
| D：投放上下文与样本扩展 | 三层草稿、有限规则、预算语义与变更影响；完成 3 商品×2 市场×2 版本 | 12 条成片对应清楚的 Ad 与资料版本，本地校验不冒充平台权限 |
| E：用户反馈与发布 | 邀请用户试用、匿名评价、采用与耗时记录、最多 6 条修订；检查邮件、权限、任务和导出 | 完成一次真实反馈驱动的迭代，能独立使用，质量与费用结果可复查 |

技术延续现有 Next.js、TypeScript、Supabase 与 Provider 接口；视频预览/合成可增加 Remotion 及格式检查工具，新增后台任务执行能力。不因概念升级而同时更换登录、数据库、模型供应商和全部 UI。详细代码任务在实际实施前按本 PRD 拆分，不在需求文档中混入未执行的开发记录。
